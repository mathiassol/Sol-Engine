# Ship-Out Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** close all six **Ready** rows in ENGINE_MAP category 18, *Build and ship
a `game.exe`*, so that a tagged commit produces a zip a stranger can download,
unzip and double-click on a Windows machine that has never had Visual Studio on
it — and so the tree's portability claim is checked by a machine rather than
asserted.

**Why now:** category 18 has **6 Ready rows, more than any other category**, and
one of them (#14) is already done and unrecorded. Two more are one step from
done: `GPU_BASELINE.md:41` already names the zip as where the VC++ runtime gets
solved, and the `ENGINE_HAS_*` guards for a backend-less build are already in
`main.cpp` — three includes and three call sites are all that is left unguarded.

**Order of execution** — dependencies first, then leverage, cheapest and safest
before the biggest unknown:

| # | Row | Task | Why here |

## What was measured before this plan was written

Nothing below is inferred. Each fact has the command that produced it.

**The VC++ runtime gap is real, and static CRT closes it.** `dumpbin
/dependents` on the current Release `game.exe` lists `MSVCP140.dll`,
`VCRUNTIME140.dll`, `VCRUNTIME140_1.dll` and eight `api-ms-win-crt-*` entries.
The `api-ms-win-crt-*` set is the Universal CRT and is inbox on Windows 10+; the
first three are the redistributable and are not. A trial build with
`CMAKE_MSVC_RUNTIME_LIBRARY=MultiThreaded$<$<CONFIG:Debug>:Debug>` removed **all
eleven**, leaving only `ole32`, `VERSION`, `USER32`, `XINPUT1_4`, `d3d12`,
`dxgi`, `KERNEL32` and `dxcompiler.dll`. Size went 1.0 MB → 1.3 MB and
`game.exe --gates` still reported **74 `(pass)`, 0 `FAIL`, exit 0**.

**The Linux blockers are four, and small.** Only **7 of 142** source files touch
a Windows API and every one is inside its own backend package, so the portable
set really is portable. What actually breaks:

1. `packages/game/CMakeLists.txt` gates the DXC install on the **option**
   `ENGINE_RHI_D3D12` (default `ON` everywhere) rather than on the **target**
   `engine::rhi-d3d12` (added only under `if(ENGINE_RHI_D3D12 AND WIN32)`). On
   Linux the option is on, `engine_locate_dxc()` finds nothing, and the
   `FATAL_ERROR` fires. **Configure dies before anything else is reached.**
2. `EngineRuntimeApp.cmake`'s `install(FILES "${CMAKE_BINARY_DIR}/cooked/content.pak")`
   is unguarded inside `APP_INSTALL_LAYOUT`. `packages/cook` is `if(WIN32)`
   because it links `assets-png-wic` (WIC), so no Linux build produces that file.
   Fails at `cmake --install`, not configure — latent, but on the same path.
3. Three unguarded includes in `main.cpp`: `shaders/dxc/shader_compiler_dxc.hpp`,
   `shaders/dxc/shader_hot_reload_dxc.hpp` and `assets/png/image_loader_png.hpp`.
4. Three call sites behind them — `main.cpp:5544`, `:5913` (`dxc::`) and
   `:4751` (`png::`). Three. Not thirty.

`Engine::init` already guards on `if (modules_.rhi)`, so a null RHI degrades
rather than crashes, and `main.cpp` already establishes the pattern this needs:
`#ifdef ENGINE_HAS_WIN32_PLATFORM … #else log(Fatal) ; return 1 #endif`.

**Build #10 is mostly built.** `WindowMode` is `{Windowed, Borderless,
Fullscreen}` with `parse_window_mode`, `IWindow::set_mode`, the cvars
`window.width`, `window.height`, `window.mode`, `r.vsync`, and F11. The whole
cvar inventory outside gate knobs is **six**: those four plus `r.aa` and
`r.exposure`. There is no cvar *writer* anywhere — `apply_cvar_file` only reads —
so persistence is out of scope by decision, and this row is quality presets.

## The two decisions, taken

**Static CRT, not a bundled redistributable.** Measured above: it removes the
requirement instead of shipping it. `GPU_BASELINE.md:41`'s redistributable row
gets **deleted**, not rewritten, and Build #9's `Do not (still): app-local
vcruntime` is honoured — the answer is that no vcruntime travels at all, app-local
or otherwise. Rejected: bundling `MSVCP140`/`VCRUNTIME140` next to the exe
(reverses that Do-not and redistributes Microsoft binaries), and shipping
`vc_redist.x64.exe` in the zip (turns unzip-and-play into a two-step install).

Safe here because the engine ships **no DLLs of its own**. The one non-system
DLL, `dxcompiler.dll`, is reached through COM interfaces — allocation and release
both happen inside it — so no CRT object crosses the boundary. The trial build's
74 passing gates exercise that path, including shader compilation and hot reload.

**Build #10 is presets without persistence.** A cvar writer is a new public API
in `core`/`engine` with its own decisions (which cvars are persistable, what
happens to a hand-edited file), which makes it Foundation work rather than a
Build row. Task 7 leaves a follow-up row for it.

## Read this before Task 1 — six project rules that will bite you

1. **There is no test framework. A test is a *gate*** — a plain function in
   `packages/sandbox/src/main.cpp` asserting on real values and logging a line
   ending `(pass)` or `(FAIL)`. Only task 7 adds one. Write it, watch it fail,
   then implement.

2. **Every commit must be green.** `--gates` exits 0 with **74 `(pass)`, 0
   `FAIL`** (75 from task 7), and `check-invariants.ps1` passes **14/14**.

3. **`docs/ROADMAP.md` is an implicit dependency of every source change.** The
   `roadmap-audit` invariant recounts C++/HLSL lines and fails if the audit line
   disagrees. Tasks 6 and 7 add source lines. Take the number from the failure
   message; it prints the recount.

4. **Never run `clang-format`.** The root `.clang-format` is `DisableFormat:
   true` and `format-hygiene` (invariant 14) fails a push that breaks
   `.editorconfig` — 100 columns, no tabs, no trailing whitespace, final newline,
   LF for sources and **CRLF for `.ps1`/`.bat`/`.cmd`**. Editing a `.ps1` with
   `sed -i` strips the CR from touched lines and turns that check red.

5. **`CMakePresets.json` is the build definition now.** A new configuration goes
   there, not into README and CI separately — that divergence is what it was
   added to end. `ci-build` deliberately sets no generator; keep it that way.

6. **Trunk-based.** Commit to `main` and push after each task. No branches, no
   worktrees, no PRs. Commit tag `(Build #N)` only when the commit closes that
   ENGINE_MAP row.

### The verification block

```powershell
cmake --build --preset debug
.\build\bin\Debug\sandbox.exe --gates
$env:ENGINE_GPU_DEBUG=1; .\build\bin\Debug\sandbox.exe --gates; $env:ENGINE_GPU_DEBUG=$null
cmake --build --preset release-game
.\build\bin\Release\game.exe --gates
pwsh -NoProfile -File tools/check-invariants.ps1
```

Expected: build clean; **74 `(pass)`, 0 `FAIL`** in both configurations (75 from
task 7); `D3D12 debug layer: 0 message(s), 0 error(s), 0 warning(s)`; `all 14
checks passed`. Use `pwsh`, not `powershell` — 5.1 needs `-ExecutionPolicy
Bypass`.

## Task 2: A prerequisite check that names what is missing (Build #16)

**Row:** #16 · **Cost:** half a day · **Closes a row:** yes

Two prerequisites already fail well: a missing Windows SDK gives a `FATAL_ERROR`
naming DXC and the SDK, and an over-long source path now warns before
`project()`. The rest fail as CMake's own errors. Missing Visual Studio gives
`No CMAKE_CXX_COMPILER could be found`; CMake older than 4.2 gives
`Could not create named generator Visual Studio 18 2026`. Neither names the
thing to install.

This cannot be an invariant — it needs a machine, and CI runners have everything.
It is a tool a person runs before their first configure.

- [ ] **2.1** Write `tools/check-prereqs.ps1`. One line per prerequisite:
  **found** with the version, or **missing** with its name and where to get it.
  Check CMake (≥ 4.2 for the documented generator, ≥ 3.24 for the project
  itself), that `Visual Studio 18 2026` is an available generator, the C++
  workload's compiler, the Windows SDK DXC pair (reusing the same search
  `cmake/EngineDxc.cmake` does, so the two cannot disagree), git, PowerShell, and
  the source path length. Exit 0 when everything needed is present, 1 otherwise.
  CRLF, and 5.1-compatible — no `??`, no ternary.
- [ ] **2.2** Make the *first* thing README's setup section says: run this, then
  configure.
- [ ] **2.3** Where CMake can name the prerequisite itself and currently does
  not, make it. At minimum, `CMakeLists.txt` should say what to install when the
  generator is a Visual Studio one and no C++ compiler is found.

**Proof:** run it on this machine — every line found, exit 0. Then control-test
by lying to it: point the DXC search at an empty directory and confirm it reports
that one line missing, names the Windows SDK, and exits 1. Runs under PowerShell
7 and under 5.1 with `-ExecutionPolicy Bypass`. `all 14 checks passed` —
`format-hygiene` covers the new script's line endings.

**Commit:** `feat(tooling): check-prereqs names what is missing (Build #16)`

## Task 7: Quality presets (Build #10)

**Row:** #10 · **Cost:** 1 day · **Closes a row:** yes

Fullscreen is already there: `WindowMode`, `parse_window_mode`,
`IWindow::set_mode`, the `window.*` cvars and F11. What is missing is a single
knob that moves several at once.

Only two real quality knobs exist today: `r.aa`, and
`StandardFrameDesc::shadow_map_size`, which is a struct field rather than a cvar.

- [ ] **7.1** Add an `r.shadow_size` cvar so the preset has something to set
  rather than reaching into a struct. Default `kShadowMapSize` (1024) so
  behaviour is unchanged. Validate it: a shadow map is a graph transient, so
  reject anything not a sane power of two rather than failing at resource
  creation.
- [ ] **7.2** Add `r.quality` — `low | medium | high` — applied **at startup**,
  setting `r.aa` and `r.shadow_size`. Startup-only is the honest scope and must
  be said in the help string: the shadow map is created during graph setup, so
  changing it mid-session means recreating a transient, which is its own row.
  An explicit `r.aa` or `r.shadow_size` in `config.cfg` or on the command line
  must **win** over the preset — a preset is a default, not an override, and
  `CvarSource` already distinguishes where a value came from.
- [ ] **7.3** **Write the gate first and watch it fail.** `run_quality_preset_gate`
  asserts each of the three presets produces the exact `r.aa` and `r.shadow_size`
  values it claims, and that an explicit setting survives the preset. Assert on
  the values, not on "it didn't crash", and put the real numbers in the message
  including on failure. That takes the gate count to **75**.
- [ ] **7.4** README: the two cvars, their accepted values, and that the preset
  is a startup default.
- [ ] **7.5** Add a Later row for persisting cvar choices to `config.cfg`, with
  *Finish first* naming the cvar writer. That is Foundation work, not Build, and
  leaving it unrecorded is how it gets rediscovered as a surprise.

**Proof:** 75 `(pass)`, 0 `FAIL`, in both configurations. Watch the gate fail
first — run it before 7.1 and 7.2 exist. `--set r.quality=low` visibly changes
AA and shadow resolution in a real session, and `--set r.quality=low --set

**Commit:** `feat(renderer): r.quality presets over AA and shadow size (Build #10)`

## What this plan does not do

No installer — CPack's ZIP generator only. Build #8 reads "Zip / installer" and
this answers the zip half; an NSIS or WiX installer buys nothing while the game
is a folder you unzip, and Build #19 (delta patching, **Far**) is the row that
would need one. No code signing (#11, **Far**), no `%LOCALAPPDATA%` logs (#7,
**Later**, blocked on Foundation #7 minidump), no non-Windows *packaging* (#17,
**Later**, blocked on Platform #9) — task 6 proves the code compiles off Windows,
which is a different claim from shipping there. No cvar persistence, by the
decision recorded above.
