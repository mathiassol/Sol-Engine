# `reflect` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A `reflect` package that describes a POD struct's fields — name, byte
offset, size, type — and can prove at compile time that the description matches
the struct it claims to describe.

**Architecture:** Plain data, no registry, no serialisation. `FieldDesc` is
`{name, offset, size, type}`; `TypeDesc` is a name plus a span of those.
`validate()` is `constexpr`, so a type can `static_assert` its own completeness
— the generalisation of the `static_assert(sizeof(FramePipelines) == count *
sizeof(void*))` idiom already in `frame_pipelines.hpp`, made to work when the
fields have different types. One `ENGINE_FIELD` macro guarantees a descriptor's
name, offset and size agree with the actual member.

**Tech Stack:** C++20, no dependencies beyond `engine::core` for the integer
typedefs. No third-party code. Verified by one CPU gate, so it runs in CI.

## Read first

**There is no test framework.** The test *is* a gate: a plain function in
`packages/sandbox/src/gates/gates_<domain>.cpp`, declared in
`gates/gates.hpp`, classified in `kGates` in `gates/gate_registry.cpp`, and
called from the sequence in `main.cpp`. See "What a gate is" in
[CLAUDE.md](../../../CLAUDE.md). Write the gate first and watch it fail.

**A C++ first red is a wrong value, not a compile error.** A gate that does not
compile has not gone red; it has not run. So each task stubs the new function
to return a deliberately wrong value, watches the gate report that value, and
only then implements. The stub is named in each task.

**Trunk-based.** Commit to `main` and push after every commit. No branches.

**Commit format:** `type(reflect): summary`. **No commit carries a
`(Category #N)` suffix** — see Task 6 Step 3 for why this plan does not close
Foundation #14.

**Every task ends green.** `pwsh -NoProfile -File tools/check-invariants.ps1`
must pass before each commit — including `doc-claims`, which will fail the
moment `packages/reflect/` exists without a row in ARCHITECTURE.md. Task 1
handles that; do not skip it.

**The LOC audit goes stale on every commit that changes source line count.**
`roadmap-audit` recounts `packages/**/*.{cpp,hpp,h,hlsl,hlsli}` (excluding
`third_party/`) and compares it to the figure committed in `docs/ROADMAP.md`.
So **any** task in this plan that adds or removes source lines must also update
that one sentence, or the run fails. Recount with:

**Do not count it yourself — ask the check.** Run the invariants; when the
figure is stale, `roadmap-audit` prints the number it recounted:

```
[FAIL] roadmap-audit    docs/ROADMAP.md: audit claims 34057 lines, recount says 34148
```

Put *that* number in the sentence and re-run. The check is the only authority
here, so reading its output cannot disagree with it.

**Do not use `Measure-Object -Line`.** An earlier version of this plan gave

```powershell
... | Get-Content | Measure-Object -Line).Lines
```

which is wrong: `-Line` does not count blank lines, because an empty string
contributes zero. On this tree it under-reports by about 4,000 — 30,211 against
the real 34,148 — and Task 2 lost time to it. If you want a second opinion
independent of the check, `(... | Get-Content).Count` counts array elements and
is correct.

Do the update **last** among a task's edits, because it goes stale again the
moment anything else is touched. Task 6 does a final recount, but do not defer
to it — every commit has to stand on its own.

## Design decisions this plan locks in

Recorded because an agent will otherwise "helpfully" undo them:

| Decision | Why |
|---|---|
| `reflect` depends on `core` only, **not `math`** | Keeps it at Layer 0. `size_of` carries a hardcoded byte count for `Vec3` etc.; the *gate* cross-checks those against `sizeof(math::Vec3)`, because the gate is in `sandbox` and can see both. That is a real assertion on independently-derived values |
| `FieldType` covers **only types that exist today** | No `Quat` (math has no quaternion type — `Vec4` is 16 bytes and is what a rotation uses for now), no `EntityId`, no `EntityRef`. Those arrive in step 2 with the types themselves. Naming a type that does not exist is the drift `VISION.md` exists to prevent |
| One macro, `ENGINE_FIELD` | It expands `#member` and `offsetof`/`sizeof` from the same token, so a descriptor cannot disagree with its member. Same justification as `ENGINE_ASSERT` capturing `__FILE__` — the macro removes a class of error rather than saving keystrokes |
| No registry, no text writer | The component registry belongs to `world` (step 2) and text I/O to `document` (step 3). YAGNI |
| Variable-size fields report `size_of == 0` | A fixed char buffer's size differs per field, so `FieldDesc` carries its own `size` and `validate` skips the cross-check for those. **This is why a forgotten enumerator is dangerous** — see Task 2b |
| `is_valid_field_type`, not `is_type` | Renamed after Task 2b's review: "is this type a type" reads as a tautology, and the predicate is really "is this in the table rather than the sentinel" |
| One table indexed by `FieldType`, not per-property switches | Task 2's review found four independent places that silently accept a new enumerator, one of which disables `validate`'s size check for it. A `Count` sentinel plus `static_assert(table_length == Count)` makes it a build error — the idiom already in `frame_pipelines.hpp` and `physics_cpu.cpp` |

```cpp
//
// This exists so that text serialisation, the command layer and an editor
// inspector are one mechanism rather than three hand-written ones that drift
// apart. See docs/superpowers/specs/2026-09-03-editor-architecture-design.md.
//
// Deliberately knows nothing about `math`: `size_of` carries byte counts for
// the vector types, and the reflect gate in the sandbox cross-checks them
// against the real `sizeof`, because that is where both are visible.
namespace engine::reflect {

// Only types that exist in the tree today. `EntityId` and `EntityRef` arrive
// with those types in step 2; a tag for a type nobody can name is drift.
enum class FieldType : u8 {
    Bool,
    I32,
    U32,
    F32,
    F64,
    Vec2,
    Vec3,
    Vec4,
    Mat4,
    // A fixed-size char buffer. Its width differs per field, so FieldDesc's own
    // `size` is authoritative and size_of reports kVariableSize.
    Name,
};

// size_of/align_of answer this for a type whose width is per-field.
inline constexpr u32 kVariableSize = 0;

constexpr u32 size_of(FieldType) {
    return 0; // STUB - Task 2 Step 6 replaces this
}

constexpr u32 align_of(FieldType) {
    return 0; // STUB - Task 2 Step 6 replaces this
}

const char* to_string(FieldType type);

} // namespace engine::reflect
```

Includes to add at the top if not already present: `<engine/reflect/field.hpp>`,

```cpp
bool run_reflect_gate() {
    using engine::reflect::FieldType;
    using engine::reflect::size_of;
    using engine::reflect::align_of;

    // Every byte count reflect hardcodes, against the type it claims to
    // describe. reflect cannot include math (it is Layer 0 and math is a
    // sibling), so this gate is the only place the two can be compared - and
    // a silent disagreement here would corrupt every offset computed from it.
    struct Expect {
        FieldType type;
        engine::u32 size;
        engine::u32 align;
    };
    const Expect expected[] = {
        {FieldType::Bool, sizeof(bool), alignof(bool)},
        {FieldType::I32, sizeof(engine::i32), alignof(engine::i32)},
        {FieldType::U32, sizeof(engine::u32), alignof(engine::u32)},
        {FieldType::F32, sizeof(engine::f32), alignof(engine::f32)},
        {FieldType::F64, sizeof(engine::f64), alignof(engine::f64)},
        {FieldType::Vec2, sizeof(engine::math::Vec2), alignof(engine::math::Vec2)},
        {FieldType::Vec3, sizeof(engine::math::Vec3), alignof(engine::math::Vec3)},
        {FieldType::Vec4, sizeof(engine::math::Vec4), alignof(engine::math::Vec4)},
        {FieldType::Mat4, sizeof(engine::math::Mat4), alignof(engine::math::Mat4)},
    };

    engine::u32 checked = 0;
    engine::u32 wrong = 0;
    FieldType first_wrong = FieldType::Bool;
    engine::u32 first_got = 0;
    engine::u32 first_want = 0;
    for (const Expect& e : expected) {
        ++checked;
        const engine::u32 got_size = size_of(e.type);
        const engine::u32 got_align = align_of(e.type);
        if (got_size != e.size || got_align != e.align) {
            if (wrong == 0) {
                first_wrong = e.type;
                first_got = got_size;
                first_want = e.size;
            }
            ++wrong;
        }
    }

    // Name is per-field, so it must report kVariableSize rather than a width.
    const bool name_variable = size_of(FieldType::Name) == engine::reflect::kVariableSize;

    const bool passed = wrong == 0 && checked == 9 && name_variable;
    char message[224];
    std::snprintf(message, sizeof(message),
        "Reflect size gate: checked=%u wrong=%u first_bad=%s(got %u want %u) "
        "name_variable=%s (%s)",
        checked, wrong, engine::reflect::to_string(first_wrong), first_got, first_want,
        name_variable ? "yes" : "no", passed ? "pass" : "FAIL");
    engine::log(passed ? engine::LogLevel::Info : engine::LogLevel::Error,
        engine::LogChannel::General, message);
    return passed;
}
```

## Task 2b: a forgotten `FieldType` becomes a build error

Added after Task 2's code review found that adding an enumerator to `FieldType`
is silently accepted in **four** independent places. This is not a defect in
Task 2's execution — it built the design the plan specified. The design was
wrong, and it has to change before Task 4 builds `validate()` on top of it.

What the review established, each verified rather than assumed:

| Hole | Behaviour on a new enumerator |
|---|---|
| `size_of` | Falls through to `return kVariableSize` → **0**. And `0` means "width is per-field, skip the cross-check", which is exactly the check `validate()` exists to perform. The new type's size stops being verified at all |
| `align_of` | Falls to `default: return 4`. Wrong for anything 8-aligned, and it feeds `validate()`'s interior-gap tolerance, so the symptom is a *false* `InteriorGapTooLarge` rejection whose cause is buried |
| Compiler | Nothing. `cmake/EngineDefaults.cmake` sets only `/W4 /permissive-`; C4061 and C4062 need `/Wall`. The Linux leg's `-Wall` would warn on `size_of`'s switch, but there is no `-Werror` |
| The gate | Nothing. `expected[]` is a hand-written allowlist, so `checked` stays 9 and the gate reports `(pass)` while blind to the new type |

**Files:**
- Modify: `packages/reflect/include/engine/reflect/field.hpp`
- Modify: `packages/reflect/src/field.cpp`
- Modify: `packages/sandbox/src/gates/gates_core.cpp`

The fix is the idiom this tree already uses twice — `frame_pipelines.hpp`'s

```cpp
// One row per FieldType, indexed by it. `size` is kVariableSize when the width
// is per-field. Byte counts for the math types are stated rather than derived,
// because reflect does not depend on math; the reflect gate compares every one
// of them against the real sizeof/alignof, and asserts it covered them all.
struct FieldTypeInfo {
    u32 size = kVariableSize;
    u32 align = 1;
    const char* name = "?";
};

inline constexpr FieldTypeInfo kFieldTypes[] = {
    {1, 1, "bool"},
    {4, 4, "i32"},
    {4, 4, "u32"},
    {4, 4, "f32"},
    {8, 8, "f64"},
    {8, 4, "vec2"},
    {12, 4, "vec3"},
    {16, 4, "vec4"},
    {64, 4, "mat4"},
};

static_assert(sizeof(kFieldTypes) / sizeof(kFieldTypes[0])
        == static_cast<usize>(FieldType::Count),
    "kFieldTypes needs exactly one row per FieldType");

// Count is a sentinel, so it is not a valid index. Guarding rather than
// asserting keeps these usable in a constant expression from a caller that has
// not validated its input yet.
constexpr bool is_valid_field_type(FieldType type) {
    return static_cast<usize>(type) < static_cast<usize>(FieldType::Count);
}

constexpr u32 size_of(FieldType type) {
    return is_valid_field_type(type) ? kFieldTypes[static_cast<usize>(type)].size : kVariableSize;
}

constexpr u32 align_of(FieldType type) {
    return is_valid_field_type(type) ? kFieldTypes[static_cast<usize>(type)].align : 1;
}
```

- [ ] **Step 5: Implement `validate`**

Replace the stub in `field.hpp`:

```cpp
// Checks a descriptor set against the struct it claims to describe. constexpr
// so a type can static_assert its own completeness, which is the generalisation
// of frame_pipelines.hpp's
// static_assert(sizeof(FramePipelines) == count * sizeof(void*)) to fields that
// do not all have the same width.
//
// The gap rules are what catch a *missing* field, and they are heuristics with
// a precise bound: padding between two fields can never be as wide as the
// following field's alignment, so a gap that wide means something is not
// described. Same reasoning after the last field, using the struct's alignment.
constexpr TypeError validate(const TypeDesc& type) {
    if (type.fields == nullptr || type.field_count == 0) {
        return TypeError::NoFields;
    }
    u32 cursor = 0;
    for (u32 i = 0; i < type.field_count; ++i) {
        const FieldDesc& f = type.fields[i];
        if (f.name == nullptr || f.name[0] == '\0') {
            return TypeError::EmptyName;
        }
        // Before the size cross-check, not after: size_of(Count) is
        // kVariableSize, so a sentinel would otherwise be waved through by the
        // `nominal != kVariableSize` test below as if it were a Name field.
        if (!is_valid_field_type(f.type)) {
            return TypeError::InvalidFieldType;
        }
        const u32 nominal = size_of(f.type);
        if (nominal != kVariableSize && f.size != nominal) {
            return TypeError::SizeDisagreesWithType;
        }
        if (i > 0) {
            const FieldDesc& prev = type.fields[i - 1];
            if (f.offset < prev.offset) {
                return TypeError::OffsetsNotAscending;
            }
            if (f.offset < prev.offset + prev.size) {
                return TypeError::FieldOverlapsPrevious;
            }
            const u32 gap = f.offset - cursor;
            // align_of never returns 0 since Task 2b's table - Name and any
            // out-of-range value both report 1 - so no guard is needed here.
            if (gap >= align_of(f.type)) {
                return TypeError::InteriorGapTooLarge;
            }
        }
        if (f.offset + f.size > type.size) {
            return TypeError::FieldPastEnd;
        }
        cursor = f.offset + f.size;
    }
    const u32 tail = type.size - cursor;
    // type.align comes from alignof() at the call site, so 0 means a caller
    // built the TypeDesc by hand and got it wrong; treat it as 1 rather than
    // dividing the tail rule by nothing.
    const u32 struct_align = type.align == 0 ? 1 : type.align;
    if (tail >= struct_align) {
        return TypeError::TrailingGapTooLarge;
    }
    return TypeError::Ok;
}
```
